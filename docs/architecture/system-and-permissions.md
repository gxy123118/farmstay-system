# 系统与权限设计

## 1. 项目定位
`farmstay-system` 是一个面向农家乐/民宿场景的综合服务平台，当前后端已覆盖：
- 游客预订
- 订单支付与退款
- 经营者民宿运营
- AI 客服助手
- AI 经营建议
- 管理员后台治理

## 2. 核心业务模块
- 认证与账号：登录、注册、个人信息、余额
- 农家乐业务：民宿、房型、活动、餐饮、优惠券
- 预订交易：订单创建、余额支付、退款、充值
- AI 助手：FAQ、推荐、能力说明、闲聊、知识库检索
- 经营分析：评论驱动的运营建议与报告
- 管理后台：用户、评论、知识库、平台统计

## 3. 角色定义
- `guest`：未登录用户
- `visitor`：游客
- `operator`：经营者
- `admin`：平台管理员

角色层级：
- `guest < visitor < operator < admin`

说明：
- 注册页仅开放 `visitor` 和 `operator`
- `admin` 为内置账号，不允许公开注册

## 4. 角色能力矩阵
| 能力 | guest | visitor | operator | admin |
|---|---|---|---|---|
| 浏览公开民宿信息 | 是 | 是 | 是 | 是 |
| 创建订单 | 否 | 是 | 是 | 否 |
| 余额支付 | 否 | 是 | 是 | 否 |
| 申请退款 | 否 | 是 | 是 | 否 |
| 发布或修改本人评价 | 否 | 是 | 是 | 否 |
| 管理自己名下民宿 | 否 | 否 | 是 | 否 |
| 使用 AI 助手 | 否 | 是 | 是 | 否 |
| 查看 AI 经营建议 | 否 | 否 | 是 | 否 |
| 用户管理 | 否 | 否 | 否 | 是 |
| 删除违规评论 | 否 | 否 | 否 | 是 |
| 管理全平台知识库 | 否 | 否 | 否 | 是 |
| 查看平台统计 | 否 | 否 | 否 | 是 |

## 5. admin 边界
当前 `admin` 只负责平台治理，不继承完整经营者业务身份。

当前支持：
- 用户管理
- 评论与内容治理
- 知识库管理
- 平台统计

当前不建议：
- 让 `admin` 直接经营民宿
- 让 `admin` 直接下单、支付、评价
- 把 `admin` 当成“超级经营者”

## 6. 后端权限校验原则
- 游客能力：`enforceAtLeastVisitor()`
- 经营者能力：`enforceOperator()` 或 `enforceAtLeastOperator()`
- 管理员能力：`enforceAdmin()`

说明：
- 经营者专属接口默认仍按“本人店铺归属”校验
- `admin` 主要通过 `/api/admin/**` 完成平台治理动作

## 7. 当前交易模式
- 充值：支付宝
- 订单支付：平台余额支付
- 退款：退回平台余额
- 支付宝当前只用于充值，不直接参与订单付款

## 8. 当前 AI 模式
- AI 助手：轻量 RAG + 意图识别 + FAQ 改写 + 推荐槽位提取
- 经营建议：结构化聚合 + MiniMax 生成 + 本地规则兜底
