# 系统与权限设计

## 1. 项目定位

`farmstay-system` 是一个面向农家乐与乡村民宿场景的综合服务平台。当前后端已覆盖以下能力：

- 游客预订
- 余额支付与退款
- 支付宝充值
- 经营者履约核销与结算
- 经营者提现申请
- AI 客服助手
- 经营者运营建议
- 管理员后台治理

## 2. 核心业务模块

- 认证与账户
  - 登录、注册、个人信息、余额、余额流水
- 农家乐业务
  - 店铺、房型、活动、餐饮、优惠券
- 预订交易
  - 订单创建、余额支付、退款、经营者核销、经营者结算、提现
- AI 助手
  - FAQ、推荐、能力说明、闲聊、知识库检索
- 经营分析
  - 评论驱动的经营建议与历史报告
- 管理后台
  - 用户管理、评论治理、知识库管理、平台统计、提现审核

## 3. 角色定义

- `guest`
  - 未登录用户
- `visitor`
  - 游客
- `operator`
  - 经营者
- `admin`
  - 平台管理员

角色层级：

- `guest < visitor < operator < admin`

说明：

- 前台注册仅开放 `visitor` 与 `operator`
- `admin` 为内置角色，不允许前台注册

## 5. 订单状态机

当前订单核心状态：

- `CREATED`
  - 已创建，待支付
- `PAID`
  - 游客已支付，待经营者履约
- `COMPLETED`
  - 经营者已核销完成，订单金额已结算到经营者余额
- `CANCELLED`
  - 未支付订单已取消
- `REFUNDED`
  - 已支付订单已退款

状态流转：

- `CREATED -> PAID`
- `CREATED -> CANCELLED`
- `PAID -> REFUNDED`
- `PAID -> COMPLETED`

限制说明：

- `COMPLETED` 后不能退款
- 经营者只能核销本人店铺的 `PAID` 订单

## 6. 经营者交易数据边界

经营者当前可查看：

- 本人名下农家乐订单
- 本人名下农家乐支付数据
- 本人名下农家乐退款数据
- 单店或多店汇总统计

经营者可执行：

- 查看订单详情
- 查看交易统计
- 对已支付订单执行核销完成
- 发起提现申请
- 查看自己的提现申请状态

经营者不可查看：

- 其他经营者的订单
- 全平台充值流水
- 全平台资金统计

## 7. 提现业务边界

当前提现方案采用：

- 经营者申请提现
- 管理员审核
- 管理员线下人工打款
- 管理员在系统中确认打款完成

状态说明：

- `PENDING`
  - 已申请，待审核
- `APPROVED`
  - 审核通过，待人工打款
- `SUCCESS`
  - 已确认人工打款完成
- `REJECTED`
  - 审核拒绝，金额退回余额

说明：

- 发起提现申请时会先扣减经营者余额
- 若审核拒绝，系统会自动退回余额
- 审核通过不代表已到账，需管理员手工打款后再确认完成

## 8. admin 边界

当前 `admin` 的职责是平台治理，不是店铺经营。

当前支持：

- 用户管理
- 评论治理
- 知识库管理
- 平台统计
- 提现审核与人工打款确认

当前不建议：

- 让 `admin` 直接经营农家乐
- 让 `admin` 直接作为游客下单、支付、评价
- 将 `admin` 等同于“超级经营者”

## 9. 后端权限校验原则

- 游客能力：`enforceAtLeastVisitor()`
- 经营者能力：`enforceOperator()` 或 `enforceAtLeastOperator()`
- 管理员能力：`enforceAdmin()`

说明：

- 经营者专属接口默认按“店铺归属”校验
- 管理员平台治理接口统一走 `/api/admin/**`

## 10. 当前交易模式

- 充值：支付宝
- 订单支付：平台余额
- 退款：退回游客平台余额
- 核销完成：结算到经营者平台余额
- 提现：审核后线下人工打款

## 11. 当前 AI 模式

- AI 助手：轻量 RAG + 意图识别 + FAQ 改写 + 推荐槽位提取
- 经营建议：结构化聚合 + 模型生成 + 本地规则兜底
