# 系统与权限设计

## 1. 项目定位

`farmstay-system` 是一个面向农家乐/乡村民宿场景的综合服务平台，当前后端已覆盖：

- 游客预订
- 订单支付与退款
- 账户余额与支付宝充值
- AI 客服助手
- 经营者运营建议
- 管理员后台治理

## 2. 核心业务模块

- 认证与账户：登录、注册、个人信息、余额、余额流水
- 农家乐业务：农家乐、房型、活动、餐饮、优惠券
- 预订交易：订单创建、余额支付、退款、充值
- AI 助手：FAQ、推荐、能力说明、闲聊、知识库检索
- 经营分析：评论驱动的经营建议与历史报告
- 管理后台：用户、评论、知识库、平台统计

## 3. 角色定义

- `guest`：未登录用户
- `visitor`：游客
- `operator`：经营者
- `admin`：平台管理员

角色层级：

- `guest < visitor < operator < admin`

说明：

- 注册页仅开放 `visitor` 和 `operator`
- `admin` 为内置账号，不允许公开注册

## 5. 经营者交易数据边界

为补齐经营者业务闭环，系统当前已支持经营者查看自己名下农家乐的订单与交易数据。

经营者可见范围：

- 当前经营者本人名下农家乐的订单
- 当前经营者本人名下农家乐的支付数据
- 当前经营者本人名下农家乐的退款数据
- 单店或多店汇总统计

经营者不可见范围：

- 其他经营者的订单
- 全平台交易数据
- 平台级充值流水

当前经营者交易侧能力：

- 查看单店订单
- 查看名下全部订单
- 按店铺筛选订单
- 按状态筛选订单
- 查看订单总数、成交总额、退款总额、退款率

## 6. admin 边界

当前 `admin` 只负责平台治理，不继承完整经营者业务身份。

当前支持：

- 用户管理
- 评论与内容治理
- 知识库管理
- 平台统计

当前不建议：

- 让 `admin` 直接经营民宿
- 让 `admin` 直接下单、支付、评价
- 把 `admin` 当成“超级经营者”

## 7. 后端权限校验原则

- 游客能力：`enforceAtLeastVisitor()`
- 经营者能力：`enforceOperator()` 或 `enforceAtLeastOperator()`
- 管理员能力：`enforceAdmin()`

说明：

- 经营者专属接口默认仍按“本人店铺归属”校验
- `admin` 主要通过 `/api/admin/**` 完成平台治理动作

## 8. 当前交易模式

- 充值：支付宝
- 订单支付：平台余额支付
- 退款：退回平台余额
- 支付宝当前仅用于充值，不直接参与订单付款

## 9. 当前 AI 模式

- AI 助手：轻量 RAG + 意图识别 + FAQ 改写 + 推荐槽位提取
- 经营建议：结构化聚合 + MiniMax 生成 + 本地规则兜底
