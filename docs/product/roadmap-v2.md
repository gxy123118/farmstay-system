# Farmstay System V2 Roadmap

## 1. 目标与范围
- 基于当前后端代码的真实能力，重构为可持续迭代的 V2 功能规划。
- 明确遗弃项、保留项、扩展项，避免继续沿用老版本的全量需求清单。
- 新增两项 AI 能力：
1. 基于 RAG 的 AI 智能客服。
2. 基于用户评价的经营建议能力（仅经营者可用）。
- 明确权限分层：`经营者 = 游客能力升级`，在租户隔离前提下拥有更高管理权限。

## 2. 当前基线（来自现有代码）
- 已有模块：认证、首页、农家乐、房型、餐饮、活动、优惠券、预订订单、评论。
- 已有角色：`visitor`、`operator`（当前代码是“严格二选一”校验）。
- 已知占位能力：
1. 支付接口为模拟支付：`POST /api/bookings/pay`。
2. 退款为模拟状态流转：`POST /api/bookings/{orderId}/refund`。
- 已有统计能力较弱，仅首页聚合概览，无经营/财务报表。

## 2.1 技术基线（2026-03-11）
- 已升级目标版本：`Java 17`、`Spring Boot 3.4.5`。
- 迁移内容：
1. 参数校验从 `javax.validation` 切换到 `jakarta.validation`。
2. OpenAPI 依赖升级到 Boot 3 兼容版本。
3. MyBatis、MyBatis-Plus、Sa-Token 依赖升级到 Boot 3 兼容版本。
- 升级目的：为后续引入 `Spring AI` 模块提供兼容运行时基础。

## 3. 遗弃与扩展策略
- 遗弃（本期不做）：
1. 视频管理与视频流能力（仅保留图片字段）。
2. 邮件/短信通知直连实现（先保留事件接口，异步通道后补）。
3. 平台级复杂 BI 看板（先提供经营者侧基础统计接口）。
- 保留（按现有代码继续）：
1. 游客搜索、详情、下单、订单、评价。
2. 经营者对农家乐/房型/服务项/优惠券/订单的管理。
- 扩展（V2 新增）：
1. 真实支付集成（支付宝/微信，统一支付单与回调验签）。
2. AI 客服（RAG）。
3. 评价洞察与经营建议（LLM + 规则融合）。
4. 经营统计与财务基础报表导出。

## 4. 分阶段计划
## Phase 1: 权限与接口基线收敛（1-2 周）
- 目标：统一角色模型与接口职责，完成“经营者是游客升级”落地。
- 交付：
1. RBAC 分层重构：`VISITOR <= OPERATOR`。
2. API 权限标签梳理，清理含糊接口说明。
3. 支付/退款接口标记兼容与迁移路径（旧路径保留，新增规范路径）。
- 验收：
1. 经营者可访问游客可见读接口。
2. 管理类接口仍严格按农家乐归属校验。

## Phase 2: 支付与订单闭环（2-3 周）
- 目标：支付能力从“模拟”升级为“可联调第三方”。
- 交付：
1. 新增支付单模型、渠道枚举、回调验签、幂等处理。
2. 订单状态机规范化：`CREATED -> PAYING -> PAID -> COMPLETED / REFUNDING -> REFUNDED`。
3. 退款单与退款回调。
- 验收：
1. 第三方沙箱联调可通过。
2. 回调重复推送不导致重复记账。

## Phase 3: AI 客服（RAG）MVP（2 周）
- 目标：支持游客和经营者在平台内问答咨询。
- 交付：
1. 知识库接入（农家乐、房型、活动、优惠、订单规则、FAQ）。
2. 检索增强问答链路（召回、重排、回答、引用片段）。
3. 会话 API 与审计日志。
- 验收：
1. 回答准确率与拒答策略可配置。
2. 不越权返回他人/他店敏感信息。

## Phase 4: 评价洞察与经营建议（2 周）
- 目标：将评论转化为经营改进建议接口。
- 交付：
1. 评论主题提取、情感聚类、问题归因。
2. 经营建议 API（优先级、预估收益、执行动作建议）。
3. 周/月趋势对比与导出。
- 验收：
1. 仅经营者可访问且仅看自己店铺。
2. 建议生成可追溯到评论证据片段。

## 5. 里程碑产物
- V2 文档与接口基线。
- 支付真实集成与订单状态机。
- AI 客服 RAG 服务与接口。
- 经营建议服务与报表导出。

## 5.1 已完成项（2026-02-26）
- 鉴权层改造：经营者可访问游客级接口能力（`VISITOR+`）。
- AI 客服 MVP 接口上线：会话创建、问答、历史消息、反馈。
- 评价经营建议 MVP 接口上线：生成报告、最新报告、历史报告、问题主题明细。

## 5.2 当前未完成项
- 正式支付通道（支付宝/微信）与回调验签链路。
- 财务对账与导出接口实现。
- AI 客服从规则+检索增强到真实外部 LLM 服务编排（Provider 与向量库）。

## 6. 风险与回滚
- 风险：
1. 角色模型改动影响旧接口鉴权行为。
2. 第三方支付回调不稳定导致状态不一致。
3. AI 输出幻觉或越权引用。
- 回滚策略：
1. 鉴权升级采用灰度开关，保留旧校验分支。
2. 支付新链路可按渠道开关关闭，回退模拟支付。
3. AI 接口可降级为 FAQ 检索结果直出。
