# Farmstay System V2 功能规格

## 1. 文档目的
- 将老版本需求与当前代码对齐，产出 V2 可执行功能范围。
- 明确哪些需求保留、遗弃、扩展。
- 强化权限边界：经营者拥有游客能力并附加经营管理能力。

## 2. 角色定义
- `游客 Visitor`：浏览、搜索、预订、支付、评论、查看自己的订单与资料。
- `经营者 Operator`：包含游客全部能力，且可管理自己名下农家乐经营数据。
- `未登录 Guest`：仅可访问公开浏览能力（首页、搜索、详情、公开评论）。

## 3. 老需求映射（遗弃/保留/扩展）
| 老需求项 | V2 决策 | 说明 |
|---|---|---|
| 首页展示 | 保留 | 继续提供概览和推荐。 |
| 搜索与筛选 | 保留并扩展 | 增加更多筛选维度与排序。 |
| 详情页图文 | 保留 | 图片保留，视频能力暂不做。 |
| 预订系统 | 保留并扩展 | 当前已支持下单，扩展真实支付和库存校验增强。 |
| 多支付方式 | 扩展 | 当前为模拟支付，V2 接入支付宝/微信。 |
| 个人中心 | 保留并扩展 | 当前主要是订单与评价，补充资料管理接口。 |
| 评论评分 | 保留并扩展 | 增加经营者评论管理与 AI 洞察。 |
| 农家乐管理 | 保留 | 已有基础 CRUD，补齐上下架策略与审核状态预留。 |
| 订单管理 | 保留并扩展 | 完善状态机、退款链路、支付对账字段。 |
| 数据统计分析 | 扩展 | 先做经营者基础经营统计与导出。 |
| 财务管理 | 扩展 | 先做收入/退款/待结算汇总，不做复杂会计核算。 |
| 消息通知 | 部分遗弃+扩展 | 本期不做短信/邮件直连；保留通知事件与站内通知接口。 |
| AI 智能客服 | 新增 | 基于 RAG，支持游客和经营者咨询。 |
| AI 经营建议 | 新增 | 基于评论和订单表现给出经营建议。 |

## 4. V2 核心功能清单
## 4.1 游客侧
- 首页：概览、推荐、活动与优惠信息。
- 搜索：按地点、价格等级、评分、房型、服务项筛选。
- 详情：农家乐信息、房型、服务项、评价、图片。
- 预订：选择入住/离店时间、服务项、优惠券，生成订单。
- 支付：发起支付、轮询结果、取消、退款申请。
- 个人中心：查看个人资料、历史订单、订单评价。
- AI 客服：行前咨询、下单咨询、优惠/活动问答。

## 4.2 经营者侧
- 经营管理：农家乐基本信息、房型、餐饮、活动、优惠券。
- 订单管理：查看店铺订单、更新状态、处理退款。
- 评论管理：查看评论列表，标记问题评论，生成整改任务。
- 经营统计：预订量、转化率、客单价、退款率、评价分布。
- 财务摘要：收入/退款/待结算，按日周月查询与导出。
- AI 建议：基于评论和订单数据生成可执行经营建议。

## 5. 新增能力详细说明
## 5.1 AI 智能客服（RAG）
- 输入：用户问题 + 上下文（角色、城市、店铺、会话历史）。
- 检索源：
1. 农家乐/房型/服务项/优惠券信息。
2. 平台规则（取消、退款、入住、发票等）。
3. 常见问答与运营公告。
- 输出：回答文本 + 证据片段引用 + 置信度/拒答标记。

## 5.2 AI 经营建议
- 输入：店铺维度评论、评分、订单、退款、服务项数据。
- 处理：主题聚类、情感分析、问题优先级排序、建议生成。
- 输出：
1. 问题摘要（例：卫生、早餐、隔音、活动组织）。
2. 建议动作（短期/中期）。
3. 预期收益（评分提升、退款率下降、复购提升）。
4. 证据链（对应评论片段与指标）。

## 6. 权限原则
- 原则 1：经营者拥有游客权限（读能力默认继承）。
- 原则 2：经营管理接口必须满足“归属校验”，仅可操作自己名下数据。
- 原则 3：支付、订单、评论等用户数据必须做“本人数据隔离”。
- 原则 4：AI 回答遵循租户隔离，禁止跨店铺敏感信息泄露。

## 7. 非功能要求
- 安全：密码盐值哈希、支付回调验签、敏感字段脱敏日志。
- 可观测：接口耗时、错误码、AI 召回率/拒答率指标。
- 可扩展：AI 模块与业务模块解耦，支持模型与向量库替换。
- 稳定性：关键写操作（支付回调、退款）需幂等。

## 7.1 技术平台要求
- 运行时基线：`Java 17`。
- 框架基线：`Spring Boot 3.4.x`。
- Jakarta 迁移要求：新代码禁止继续引入 `javax.validation.*`，统一使用 `jakarta.validation.*`。
- AI 扩展要求：后续 `Spring AI` 接入必须基于 Boot 3 兼容依赖，不再接受 Boot 2 双栈兼容方案。

## 8. 交付边界（V2）
- 必做：
1. 权限层级重构。
2. 支付真实集成（至少一个渠道先联调通过）。
3. AI 客服 RAG API。
4. AI 经营建议 API。
- 可延后：
1. 视频内容管理。
2. 短信/邮件三方通道。
3. 平台级复杂 BI 看板。

## 9. 实现状态（2026-02-26）
- 已实现：
1. 权限层级重构（经营者继承游客接口访问能力）。
2. AI 客服 API 骨架（会话、消息、反馈）。
3. AI 经营建议 API 骨架（生成、查询、历史、问题明细）。
- 未实现：
1. 第三方正式支付与退款回调。
2. 报表导出与财务结算明细接口。
3. AI 外部 LLM Provider 与向量库接入（当前为 MVP 检索+规则回答）。
